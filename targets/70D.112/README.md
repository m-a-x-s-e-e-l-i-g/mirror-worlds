# 70D 1.1.2 native-capture research

`native-research.json` records anchors from the identified ROM1 input. The standard Mirror Worlds build continues to select no native backend on the 70D. An explicit unshipped main-module variant includes the research backend. It now passes three Canon-saved mirrored RAW captures and pre-capture cancellation recovery in one emulator boot, using synthetic preview/sensor input and software control. Real Canon LiveView, physical keys and hardware operation remain unverified. The data contains no camera dump.

Initial isolated emulator experiments reached Canon's capture-job creation, `scsCapReady`, a generated dark-frame readout, the proposed stage call, and a dedicated lossless compression path. A guarded GDB observer confirmed the stage caller/context and the same source in the lossless descriptor (5568 x 3708, 14 bits). The reproducible patches, exact limits and local evidence receipts are described in [emulator-research.md](emulator-research.md). Those initial stage observations did not establish a completed photo; the later CR2 and ARM experiments below extend that evidence.

The baseline experiment saves an actual Canon CR2 in the virtual card. Independent LibRaw decoding matches all 20,646,144 RAW pixels against a separate generated-sensor ROI oracle, including Canon's two-slice ordering. Synthetic preview/thumbnail replies and the missing output-DMA pop completion unblock file writing. This establishes a simulated unmodified photo pipeline. See [the CR2 experiment](emulator-research.md#canon-cr2-output-and-slice-order) and [development bindings](lcd-research.json).

An [isolated ARM probe](emulator-research.md#isolated-arm-mirror-probe) now also saves correctly mirrored CR2s: right-half reflection and all four edges at thirds. Independent LibRaw checks every RAW pixel against a separate Bayer-cell oracle and confirms 684,288 calibration/margin pixels remain unchanged. The two mirrored shots run in one boot with different capture jobs and reused buffers. This uses the real Mirror transform in an unshipped probe; `mirror.mo` still selects no native backend on the 70D. Cancellation/shutdown, the full setting matrix and the ordinary preview/shutter path remain to be integrated and tested.

The candidate stage stub has 24 matching four-instruction sequences in this ROM; scanning for its bytes alone is ambiguous. A direct branch at `0xff15c4cc` ties `0xff361910` to `PreDevelopState.c`. The caller loads its context from a ROM literal (`0x7c15c`) into r10 and accesses the capture-job pointer at offset `0xac`. EOS M's corresponding code uses offset `0xb4`. Mirror's backend now owns that offset; capture code must not hard-code the EOS M value when a new backend is added.

## Main-module research variant

Build explicitly with:

```sh
python tools/build_module.py --module mirror --upstream --research-70d --runtime wsl --wsl-user root
```

This stages a separate `mirror_70d_research` source folder and writes `build/research/mirror-70D.112/`; it preserves standard module outputs and existing camera candidates. `MIRROR_70D_RESEARCH` enables the 70D backend in the actual main capture gate. The backend owns its five observer sites, job offset, CPSR/alignment constraints, 5648 x 3720 sensor geometry, completed DMA row count 3719 and persistent flags `0x20000000`. EOS M retains its own geometry and zero-flags contract. The packager rejects research manifests before publishing any files.

The dev3 host test executes all 44 full-size reflection layouts for each backend and checks every Bayer value, including unchanged margins. Fourteen 70D rejection cases cover wrong flags/count/stride, busy DMA, invalid context/CPSR/alignment, absent shutter/delivered preview, competing consumers during the hold, cancellation, shutdown and changing DMA state. These tests execute the main gate and transform with address/undefined-behavior sanitizers; they do not establish Canon scheduling or hardware safety.

Run `70d-capture29` loaded main research module SHA-256 `b03ecb3cdfccdb6861607903c1a5ecf2cca47851ffd6576a8d635740b6d3f2d0` as version `0.3.0-dev3`, status `OK`, on the coherent 70D core. Canon's LiveView button sets `lv=1` and creates the expected buffer table at `0x7e1c24`, but the display pointer at `0x7b4d8` remains zero. The last `gmtActivateConductor` mask is `0x35`; ROM code at `0xff1727a4` requires `0x37`. The missing activation bit is `0x02`; its event source is not yet identified. No displayed frame, shutter latch or main-module mirrored CR2 was verified. The effect remained OFF with zero capture hooks installed in this initialization run.

Four unmapped reads also appear during the run, at `0x7fffffff`, `0x80000000`, `0x80000004` and `0x80000006`. A broad GDB task-name inspection read invalid task entries during this session; attribution of these reads is unverified. The run is not labelled clean capture evidence. QEMU stopped normally through QMP. `build/research/mirror-70D.112/70D.112-main-observation.json` references 81 verified immutable file hashes, including the exact module, sources, host test logs and emulator observations. It is deliberately separate from the isolated ARM probe and compatibility matrix's normal-module capture status.

That caller also reaches the getter wrapper at `0xff2229a4`, tying the guarded getter site `0xff2229b0` to the stage path. The nearby setter entry is recorded for further investigation. Three `TwoInTwoOutJpegPath.c` anchors share the EOS M guard bytes and nearby Canon assert labels. Their active 70D capture roles still need tracing; a byte/source-label match is insufficient for installing production hooks.

The stock emulator boots Canon and ML and initializes the actual `mirror.mo`. Canon's menu responds and renders. A LiveView button event sets ML's LiveView flag, but no frame buffer becomes available in that run. A local emulator-only driver invokes Canon's normal `Release` event procedure from a DryOS task. The stock MPU model leaves `PROP_REMOTE_SW1` unanswered and Canon later reports `Not SW1 Ack!!`.

Separate, hash-labelled experimental emulator binaries explored the replies without changing the pinned source or released module. Echoing a result value of one produced Canon's rejection status. A zero-result SW1 reply advanced to a distinct SW2 request (`08 06 04 17 01 03 00 00`). Matching and acknowledging both requests suppresses the acknowledgement timeouts, but no sensor DMA, capture job or saved photo was observed. These guessed replies are **not** a captured mechanical shutter sequence or a validated emulator capture model.

The [dev9 main-module regression](emulator-research.md#repeated-main-module-capture-regression) checks three consecutive photos with changing settings, cancellation before mutation, OFF/ON recovery and final workspace cleanup. Independent LibRaw decoding verifies 61,938,432 saved RAW pixels and unchanged margins. The stock emulator and normal shared module are preserved. Next, establish real Canon LV delivery and physical-key integration, expand native full-flow settings/failure coverage and obtain owner hardware validation. Software fixture success does not prove physical camera ownership or timing. Camera-owner testing must compare actual original/mirrored CR2 output and normal shutter, autofocus, review, cancellation and shutdown behavior.

Local research evidence is in `.cache/70d-liveview/`, `.cache/70d-capture3/` (stock capture attempt), `.cache/70d-capture7/` (SW1-only acknowledgement), `.cache/70d-capture8/` (both acknowledgements), and `.cache/70d-native-port/`. Experimental binaries/patches are under `build/qemu-eos-70d-research*/`. The original QEMU source and binary remain the pinned baseline. The GUI screenshot is an emulator screenshot, not camera evidence; LiveView/render/capture support is not promoted by it.
